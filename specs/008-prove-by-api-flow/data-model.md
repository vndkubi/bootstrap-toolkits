# Prove-by-API-Flow — Data Model

> Generated by: plan-implementation
> Spec: [spec.md](./spec.md) v0.2 · Research: [research.md](./research.md)
> Date: 2026-04-24

This feature adds **no runtime domain entities** to a target repo. All entities described here are **artifacts of the `/autorun` loop itself** — files, trace records, config objects, and control signals. The formal JSON schemas live under [contracts/](./contracts/); this document captures their relationships, invariants, and lifecycle.

---

## Entity map

```
 AutorunSession ──1────* TraceRecord
       │
       ├──1────? ConfirmationGate   (emitted when the session pauses)
       │
       ├──1────1 EvidenceBundle     (assembled in Phase 7)
       │
       ├──1────1 AutorunConfig      (resolved at Phase 0)
       │
       └──1────? MockException      (written if internal mocks are unavoidable)

 AutorunAllowlist   (repo-level, not per-session)
 TaxonomyDecision   (per-feature, produced in Phase 2)
```

## 1. AutorunSession

Represents one invocation of `/autorun <PBI>`. Its identity is `(pbi, startedAt)`; its filesystem footprint is the feature workspace + the autorun branch + the trace file.

| Field | Type | Source | Notes |
|---|---|---|---|
| `pbi` | string | CLI/agent input | Resolved via precedence in US-A1 AC-1 |
| `slug` | string | `specify-feature` | Kebab-case feature slug |
| `branch` | string | derived | Always `autorun/<pbi>` |
| `startedAt` | ISO-8601 | runtime | UTC |
| `harness` | enum | detected | `vscode` \| `cli` |
| `phase` | 0..7 | runtime | Current phase |
| `status` | enum | runtime | `running` \| `gated` \| `aborted` \| `reverted` \| `completed` |
| `resumeToken` | opaque string? | on gate | `base64url(random(24))` |
| `tokenCost` | integer | accumulated | Sum across phases |
| `config` | AutorunConfig | resolved | See §5 |

**State machine**:

```
              ┌──────── --abort ───────────────┐
running ─────▶│                                ▼
   │          gated ── --resume ──▶ running ──▶ aborted
   │                                  │
   └─── phase==7 ──▶ completed        └── --revert ──▶ reverted
```

**Invariants**:
- `branch` MUST exist for every non-`aborted` session.
- `status=aborted` ⇒ working tree clean and branch head unchanged from base.
- `resumeToken` is present iff `status=gated`.
- `completed` ⇒ an EvidenceBundle exists with `status=complete`.

## 2. TraceRecord

JSONL line appended to `.github/.traces/autorun-<PBI>.jsonl` after every meaningful event.

Two record types: `meta` (first line only) and `event` (everything after).

```ts
type MetaRecord = {
  kind: "meta"
  schemaVersion: "1"
  pbi: string
  slug: string
  harness: "vscode" | "cli"
  toolkitVersion: string       // from .github/VERSION
  startedAt: string            // ISO-8601
}

type EventRecord = {
  kind: "event"
  schemaVersion: "1"
  phase: 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7
  agent: string                // e.g. "@business-analyst", "api-test-author"
  action: string               // kebab-case, e.g. "generate-contract", "run-tests"
  inputs?: object              // small summary, redacted
  outputs?: object             // small summary, redacted
  durationMs: number
  tokenCost: number
  gate?: string                // gateId if this event raised a gate
  articleXCompliant?: boolean  // set by @functional-reviewer in Phase 6
  error?: { code: string, message: string }  // redacted
}
```

**Invariants**:
- First line is always `MetaRecord`; subsequent lines are `EventRecord`.
- `schemaVersion` is frozen within one session; bumps require migration notes under [docs/](../docs).
- `inputs`/`outputs` MUST pass the redaction policy (R-5) before write.

**Consumers**: `review-effectiveness`, `repo-memory-promoter`, `correction-ledger`.

## 3. ConfirmationGate

Structured pause point. Schema lives at [contracts/gate.schema.json](./contracts/gate.schema.json). Summary:

| Field | Type | Notes |
|---|---|---|
| `schemaVersion` | `"1"` | |
| `phase` | 1..7 | |
| `gateId` | kebab-case | Stable id; `taxonomy-ambiguous`, `authz-shell-exec`, `article-x-violation`, etc. |
| `question` | string | One sentence |
| `options` | string[]? | Enumerated answers |
| `default` | string \| null | Auto-answer on a non-blocking gate (never for `authz`/`security`) |
| `blocking` | boolean | Must halt the session |
| `resumeToken` | string | Matches the session's current token |
| `category` | enum | `business` \| `authz` \| `security` \| `taxonomy` \| `config` |
| `evidence` | string[]? | Paths or links the user may inspect |

**Invariants**:
- `category ∈ {authz, security}` ⇒ `blocking=true` and `default=null`.
- Every `gateId` is registered in [contracts/autorun-gates.md](./contracts/autorun-gates.md); unknown ids are rejected at emit time.
- A session has at most one **open** gate at a time.

## 4. EvidenceBundle

A directory + a committed summary. Relationship:

```
.artifacts/<PBI>/                  (git-ignored by default)
├── api-trace.log                  (redacted HTTP request/response transcripts)
├── test-report.{xml,json,junit.xml}
├── coverage.{xml,lcov,json}
├── sequence.md                    (Mermaid as-is → to-be)
├── abort-stash.patch              (present only if --abort used)
└── mock-exceptions.md             (present only if Article X exception applied)

specs/<id>-<slug>/evidence-summary.md   (committed)
```

`evidence-summary.md` structure (fixed):

```md
# Evidence — <PBI>

- Test report: [link] (pass: X, fail: Y, skipped: Z)
- Coverage: X.X% lines, Y.Y% branches (changed module only)
- API trace: [link] (N requests, M distinct endpoints)
- Sequence diagram: [link]
- Mocks used: [category, rationale]
- Article X: ✅ | ⚠️ (see mock-exceptions.md) | ❌ BLOCKED
- Trace: .github/.traces/autorun-<PBI>.jsonl
```

**Invariants**:
- A `completed` session MUST produce `evidence-summary.md`; PR body links all items above.
- `mock-exceptions.md` exists ⇒ it contains `ratified: true` + two distinct signatures.
- All files in `.artifacts/<PBI>/` pass the secrets-scan gate before `evidence-summary.md` is committed.

## 5. AutorunConfig

Resolved from `.github/autorun.config.json` at session start. Schema: [contracts/autorun.config.schema.json](./contracts/autorun.config.schema.json).

Fields already enumerated in spec §8.2. Lifecycle:

- Parsed on session start; unknown keys ⇒ `gateId: config-unknown-key` (category `config`).
- Immutable within a session (changes mid-run require a new `/autorun`).
- Defaults baked into the agent prompt; file may be absent.

## 6. AutorunAllowlist

Repo-level file `.github/autorun.allowlist` (optional; CLI mode only).

```yaml
# .github/autorun.allowlist
# Required in CLI mode; ignored in VS Code (hook handles consent there).
version: 1
commands:
  - id: run-tests
    patterns: ["mvn test", "mvn -pl * test", "dotnet test", "pytest"]
  - id: start-stack
    patterns: ["docker compose up -d", "make dev"]
  - id: lint
    patterns: ["mvn verify -DskipTests", "dotnet format", "ruff"]
```

**Invariants**:
- In CLI mode, Phase 5 refuses to execute any command that does not match at least one pattern.
- Shell metacharacters in `patterns` are treated literally (no shell expansion); `*` is a wildcard matching one token.
- Missing file in CLI mode ⇒ `gateId: authz-no-allowlist`.

## 7. TaxonomyDecision

Per-feature, stored in spec `front-matter` as `taxonomy: <value>` and in the trace.

Enum values: `api-rest` \| `api-graphql` \| `api-grpc` \| `event-driven` \| `library` \| `cli` \| `ui-only` \| `mixed`.

**Invariants**:
- Exactly one primary taxonomy per feature; `mixed` carries `taxonomy.secondary: [..]`.
- `api-*` / `event-driven` / `mixed` ⇒ `contracts/` MUST contain at least one of (openapi.yaml | schema.graphql | *.proto | asyncapi.yaml).
- `library` / `cli` / `ui-only` ⇒ `contracts/` is absent; rationale recorded in trace `action="skip-contract"`.

## 8. MockException

Present only when internal mocking is unavoidable.

```md
# Mock Exception — <PBI>

## Rationale
<why the real internal service cannot be exercised>

## Scope
- Service: <name>
- Test files: [..]
- Expiry: <YYYY-MM-DD>  (max 30 days)

## Rollback Plan
<exact steps to remove the mock once the blocker is lifted>

## Signatures
- Owner: <github handle>, <date>
- Tech Lead: <github handle distinct from Owner>, <date>

ratified: true
```

**Invariants**:
- Two distinct signatures; lint rejects identical handles.
- `ratified: true` MUST be present for `@pr-manager` to allow ready-for-review.
- `Expiry` in past ⇒ `@functional-reviewer` downgrades verdict on next review.

## Relationship summary

| Entity | Persisted at | Lifecycle | Read by |
|---|---|---|---|
| AutorunSession | Implicit (branch + trace + workspace) | Per `/autorun` invocation | orchestrator prompt |
| TraceRecord | `.github/.traces/autorun-<PBI>.jsonl` | Append-only, kept indefinitely | `review-effectiveness`, `repo-memory-promoter` |
| ConfirmationGate | Stdout (CLI) / chat panel (VS Code) + trace `gate` field | Ephemeral; one open at a time | User |
| EvidenceBundle | `.artifacts/<PBI>/` + committed `evidence-summary.md` | Bundle ephemeral, summary committed | `@pr-manager`, reviewers |
| AutorunConfig | `.github/autorun.config.json` | Repo-scoped, edited by team | Every phase |
| AutorunAllowlist | `.github/autorun.allowlist` | Repo-scoped, CLI-only | Phase 5, post-edit hook |
| TaxonomyDecision | `spec.md` front-matter + trace | Per feature | Phase 2, review |
| MockException | `.artifacts/<PBI>/mock-exceptions.md` | Per feature, expires | `@functional-reviewer`, `@pr-manager` |
