### 3.1 Entry & session management

- `prompts/autorun.prompt.md` (≤ 4 KB) encodes the 7-phase state machine. It delegates phase bodies to existing skills; its own responsibility is phase dispatch, trace emission, gate emission, and branch bookkeeping.
- `skills/resolve-pbi-ref` implements the precedence chain (folder → GitHub → Jira → freetext). Returns `{pbi, slug, source, body}` or a `pbi-ambiguous` gate.
- `skills/autorun-branch` wraps git operations: create/detect `autorun/<pbi>`, per-phase commit, `--abort` reset, `--revert` cleanup.
- `skills/sanitize-untrusted-input` scans PBI text and any external body for injection patterns (see research R-5). Wraps suspect segments in `<UNTRUSTED>` tags before the orchestrator merges them into context.

### 3.2 Trace + gate emission

- Single small TypeScript snippet (embedded in the orchestrator prompt as a fenced code block for reference, not executed) documents the append-JSONL pattern + the gate schema. The agent itself writes records using the workspace file tools.
- Validators (runtime): the orchestrator validates every gate object against [gate.schema.json](./contracts/gate.schema.json) **before** emitting; invalid gates raise a `config-unknown-key` gate (dogfood).
- Cost cap tracker is a running sum `tokenCost` in the session; exceeding `cost.tokenCap * 0.9` emits `cost-cap-approaching` (non-blocking); exceeding the cap halts with exit 40.

### 3.3 Security layer (redaction + authz)

- `skills/redact-sensitive-data` centralizes the deny-list (research R-5). Called before any write to the trace file or evidence bundle.
- Hook integration (research R-1/R-9): Phase 5 asks for permission via `hookSpecificOutput.permissionDecision`; the existing hook contract already supports this (see user memory on `hookSpecificOutput`).
- CLI mode: Phase 0 reads `.github/autorun.allowlist`; missing → `authz-no-allowlist` gate.

### 3.4 Harness detection + orchestrator routing

- Detection: `process.env.COPILOT_HARNESS === "cli"` → CLI mode; otherwise VS Code agent context (existing patterns). The orchestrator branches its **output rendering** only — state logic is identical.
- `@dev-orchestrator` gets one new routing row: `/autorun <ref>` → `prompts/autorun.prompt.md`. All other routes unchanged (preserves NFR-6).

### 3.5 Contract-first enforcement

- `skills/generate-api-contract` reads the classified taxonomy and emits the right protocol artifact (research R-3) under `specs/<id>-<slug>/contracts/`.
- `skills/run-local-stack` detects devcontainer > docker-compose > `make dev` > native, in that order, and runs a healthcheck. Halts at `quickstart-healthcheck-failed` gate on failure.
- `plan-implementation` skill is patched with: "if `taxonomy ∈ {api-rest, api-graphql, api-grpc, event-driven, mixed}` and `contracts/` is empty, block and raise `contract-invalid`".

### 3.6 Test-first + fixtures

- `agents/api-test-author.agent.md` is a Phase 3 specialist that consumes the contract + ACs and produces **failing** integration tests mapped 1-1 to ACs. It selects the test stack by repo evidence (not defaults).
- `@mock-data-specialist` gains two responsibilities: (a) emit reusable testfixture builders + DB seeds; (b) run the PII scan on generated stubs (research R-7).
- Article X is enforced in two places: `@functional-reviewer` emits `articleXCompliant` (see §3.8); `@pr-manager` refuses ready-for-review when `articleXCompliant=false` and no ratified `mock-exceptions.md`.

### 3.7 TDD loop + post-edit hook

- `skills/tdd-implement-loop`: red → green iteration with configurable `maxIterations`/`noProgressThreshold` (see `autorun.config.schema.json`).
- Scoped regression (US-C3 AC-3): the skill calls the existing `impact-analysis` skill (research R-8) to get the module filter. Falls back to full regression when `impact-analysis` is absent.
- `scripts/post-edit-run-tests.js` retained as the optional helper surface; emit `hooks/post-edit-run-tests.json` only when explicitly enabled. Safeguards per research R-9: branch-gated + cost-cap-aware + scoped test only.

### 3.8 Review + evidence

- `review-code-changes` skill extended to accept an `--evidence-bundle <path>` input; findings cite evidence paths.
- `@functional-reviewer` emits a structured result `{verdict, findings[], articleXCompliant: bool}`.
- `@pr-manager` template `templates/pr-body.autorun.md` contains: summary, gate checklist, Mocks-used table, evidence links, Article X status line.
- `specs/<id>-<slug>/evidence-summary.md` (committed) is the anchor; `.artifacts/<PBI>/` stays local (default) per research R-4 + spec §9 Reversibility.

## 5. Implementation Strategy

### Phased rollout (matches spec §12 Milestones)

| Phase | Deliverable | Gate to next |
|---|---|---|
| **0 — Spike** | R-1 Copilot CLI decision doc appended to [research.md](./research.md) | Decision recorded, fallback path chosen |
| **A — Autorun skeleton** | `autorun.prompt.md`, `resolve-pbi-ref`, `autorun-branch`, `sanitize-untrusted-input`, `redact-sensitive-data`, harness detect, trace emitter, gate emitter, cost tracker | CLI smoke test passes; 1 dry-run on a toy PBI with all 7 phases as no-ops |
| **B — Contract-first** | `generate-api-contract`, `run-local-stack`, patch `plan-implementation`, taxonomy gate | Valid OpenAPI + healthcheck on golden Java repo |
| **C — TDD + fixtures** | `api-test-author` agent, `generate-api-flow-tests`, extended `mock-data-specialist`, `tdd-implement-loop`, optional post-edit test hook/helper, Article X in constitution | Red→green loop completes a toy feature on golden Java + .NET repos |
| **D — Review + evidence** | `review-code-changes` patch, `functional-reviewer` patch, `pr-manager` patch + `pr-body.autorun.md`, `evidence-summary.md` generator | PR opens on golden repo with full evidence bundle; `articleXCompliant` enforcement verified by a negative test |

### Ordering rules

- Phase 0 must complete before Phase A's CLI-specific tasks start; VS Code-specific tasks can run in parallel.
- **Article X PR ships with Phase C**, not earlier, to avoid blocking unrelated work before enforcement is wired.
- Every new skill ships with its **contract test** in the same PR. No skill lands without automated verification.

### Co-location

Modifications to existing files (`dev-orchestrator`, `plan-implementation`, `update-spec`, `review-code-changes`, `mock-data-specialist`, `pr-manager`, `functional-reviewer`) are bundled with the new artifacts that depend on them, not in a single omnibus PR.

## 6. Verification Strategy

Commands assumed runnable locally in the bootstrap repo + in the golden target repos (Java/Maven + .NET).

### Schema + contract tests (add to this repo's CI)

| Command | Passes when |
|---|---|
| `ajv validate -s contracts/trace.schema.json -d '.github/.traces/*.jsonl'` (line-by-line) | All trace lines valid |
| `ajv validate -s contracts/gate.schema.json -d fixtures/gates/*.json` | Sample gates valid |
| `ajv validate -s contracts/autorun.config.schema.json -d .github/autorun.config.json` | Config valid |
| Markdown lint on `specs/008-*/**/*.md` | No broken internal links |

### Skill contract tests

Each new skill ships with a `skills/<name>/tests/` folder containing input→output fixtures. Executed via a lightweight runner invoked by the existing toolkit test script.

### CLI smoke matrix

Runs on Linux + macOS + Windows, two harnesses (VS Code extension host + Copilot CLI headless), one golden repo per stack (start with Java; add .NET once Phase C lands). Verifies:

1. `/autorun` on a prepared PBI reaches Phase 7 (or a specified gate) on both harnesses.
2. Exit codes match [autorun-cli.md](./contracts/autorun-cli.md).
3. Trace file validates.
4. Evidence summary is committed.
5. `--abort` leaves a clean working tree.

### Acceptance-criteria coverage check

AC ↔ test traceability is a **target-repo concern**, not a toolkit concern. Each generated project should produce a stack-appropriate coverage verifier (Java: JUnit @Tag scan; .NET: Trait scan; pytest: pytest-cov + marker grep) during `/bootstrap-copilot`. The toolkit does not ship a single verifier script because file layouts and test markers differ per stack.

### Honesty caveat

The CLI smoke matrix cannot run in the current chat environment. The plan assumes CI (GitHub Actions + self-hosted runner) will execute it on PR to this repo. Local dev runs only the schema + markdown tests.

## 7. Risks And Rollback

| # | Risk | Likelihood | Impact | Rollback |
|---|---|---|---|---|
| 1 | Copilot CLI lacks native resume → Fallback A needed | Med | Low | Fallback A is the default; no actual rollback required |
| 2 | Copilot CLI cannot run prompts headless at all | Low | High | Mark CLI harness `experimental` in Phase A; re-open NFR-3; ship VS Code first |
| 3 | `@dev-orchestrator` routing change breaks an existing agent flow | Low | High | Routing addition is additive; revert = delete one row. Covered by existing regression smoke set |
| 4 | Article X blocks legitimate pattern we didn't foresee | Med | Med | ADR exception path is shipped alongside Article X (mock-exceptions.md); worst case revert Article X commit |
| 5 | Trace schema churn during Phase A forces re-emit | Med | Low | `schemaVersion` lets consumers stay on v1 during v2 rollout |
| 6 | Post-edit hook loops when mis-configured | Low | High | Opt-in default `false`; branch-gated; cost-capped. Kill switch: flip config key |
| 7 | Secret scanner picks a tool absent on the user's box | Med | Low | `secretScanner.tool = auto` with `gitleaks` fallback; pre-flight check prints install hint |
| 8 | Evidence bundle bloats local disk | Med | Low | `.gitignore` by default; `artifacts.mode = ci-upload` option |

### Per-phase rollback points

- Phase A: revert the `/autorun` routing row and delete `prompts/autorun.prompt.md` + 4 new skills. No target-repo code is touched.
- Phase B: delete `contracts/` generator + taxonomy gate; `plan-implementation` patch is small (one paragraph) and revertable.
- Phase C: Article X commit is a single-file change in `constitution.md`; revert = drop the commit. The TDD loop skill is self-contained.
- Phase D: `pr-manager` template additions are append-only — PRs continue to render even if fields are missing.
