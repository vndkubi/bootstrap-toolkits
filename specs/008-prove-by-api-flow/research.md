## R-1: Copilot CLI headless semantics (design-blocking spike)

**Drives**: NFR-3, US-A2 AC-1/3/5/6, FR-A4, FR-A5a, §8.1 CLI exit-code rule.

**Question**: Can Copilot CLI (a) invoke a custom prompt non-interactively, (b) emit structured JSON on stdout when a confirmation gate fires, (c) accept a `--resume` flag with an opaque token, and (d) return a process exit code we control?

**Status**: ⏳ Unresolved. Spike required before Phase A implementation (not before plan approval).

**Spike plan** (timebox 4 hours, owner: Platform Engineer):

| Step | Action | Pass criterion |
|---|---|---|
| 1 | Read Copilot CLI source under `vscode-copilot-chat/` — locate prompt loader + session serialization | Identify the entry point and session format |
| 2 | Invoke `/autorun` via CLI with `--prompt-file` (or equivalent) | Prompt runs end to end |
| 3 | Inject a gate mid-run; check stdout + exit code | Gate JSON on stdout, non-zero exit |
| 4 | Resume with a token payload | Session re-attaches at the same phase |

**Decision paths**:

| CLI capability | Plan impact |
|---|---|
| ✅ All four supported | Use native CLI resume. No design change. |
| ⚠️ Non-interactive works but no native resume | **Fallback A**: emit resume token as a file at `.github/.traces/autorun-<PBI>.resume.json`; `/autorun --resume` reads it. Same UX, slightly less elegant. |
| ❌ Non-interactive mode missing | **Fallback B**: mark CLI harness as `experimental`, ship VS Code first, re-open NFR-3. Requires spec update. |

**Decision rule**: ship Fallback A by default even if native resume works — it also benefits CI replay.

## R-2: Trace JSONL format

**Drives**: FR-A3, NFR-4, US-D3.

**Options considered**:

| Option | Pros | Cons |
|---|---|---|
| JSONL (one JSON object per line) | Streamable, tail-friendly, easy to append, easy to parse line-by-line | Harder to represent deeply nested sub-traces |
| Single JSON document (array) | Schema-validator friendly | Cannot append without rewriting; breaks on crash |
| OpenTelemetry spans | Industry standard, tool ecosystem | Heavy dep, requires exporter, overkill for local file |

**Decision**: **JSONL**. Every phase append-writes one line. Schema versioned via a top field; first line of the file is a `meta` record with `{schemaVersion, pbi, harness, startedAt}`.

**Rationale**: Local tool, partial writes must survive `--abort`, consumers (`review-effectiveness`) process streams.

**Rationale**: one artifact per protocol, industry-standard formats only, each has a CLI validator that can run inside the post-edit hook.

## R-4: Branch isolation + abort semantics

**Drives**: US-A1 AC-5, §9 Reversibility, NFR-2.

**Decision**: every `/autorun <PBI>` creates `autorun/<PBI>` from `HEAD` on first phase. All edits are committed to this branch per phase (commit message prefix `[autorun P<N>]`). `--abort` runs `git reset --hard <branch-base>` and stashes uncommitted artifacts into `.artifacts/<PBI>/abort-stash.patch`.

**Why not worktrees**: added complexity; most repos have clean working trees when `/autorun` starts. Detection + halt if dirty.

**Why commits per phase**: lets `--from-phase N` re-anchor cleanly; makes the PR audit trail obvious; enables Phase 6 to diff exactly what changed in each phase.

## R-5: Secrets redaction strategy

**Drives**: NFR-5, FR-D6, US-C2 AC-5, US-D2 AC-5.

**Sources of leakage**:
1. Request/response body captured by integration tests → `api-trace.log`.
2. Process env leaked into error messages → trace JSONL.
3. Fixtures copied from a real system → WireMock stubs.

**Policy**:
- **Deny list (redact before write)**: headers matching `(?i)^(authorization|cookie|set-cookie|x-api-key|proxy-authorization)$`; env vars matching `(?i).*(_KEY|_TOKEN|_SECRET|_PASSWORD|_PWD|_CREDENTIAL)$`; JWT payload claims `email`, `sub`, `name`.
- **Signature scan (block commit)**: `detect-secrets` (Python) or `gitleaks` (Go) — whichever ships with the repo's existing pre-commit config; add one if absent.
- **PII scan on stubs**: regex scan for emails, phone numbers, credit card patterns (Luhn check) + `detect-secrets`.

**Rationale**: layered defense. Regex redaction at write time keeps bad data out of trace; signature scan at commit time is the enforcement gate.

## R-6: Gate exit-code scheme (CLI)

**Drives**: §8.1, US-A2 AC-3/AC-5.

| Exit code | Meaning |
|---|---|
| 0 | Success, PR ready |
| 1 | Unexpected error |
| 2 | Invalid input / CLI usage |
| 10 + N (11..17) | Phase N emitted a confirmation gate |
| 20 + N (21..27) | Phase N failed (tests red past budget, contract invalid, etc.) |
| 30 | AuthZ denied |
| 31 | Article X violation without ADR |
| 40 | Cost cap hit |

**Rationale**: distinguishable in CI (shell `case $?`) without parsing stdout.

## R-7: PII / secrets scanner selection

**Drives**: NFR-10, FR-D7.

| Tool | Lang | Pros | Cons |
|---|---|---|---|
| `detect-secrets` (Yelp) | Python | Plugin model, baseline file, widely used | Python dep |
| `gitleaks` | Go | Fast, single binary | Rules less curated out of the box |
| `trufflehog` | Go | Entropy + verified provider checks | Verification hits network; too heavy for local gate |

**Decision**: **detect a pre-existing scanner in the target repo first**; use it. If none, default to `gitleaks` (single binary, zero deps). Rationale: `copilot-bootstrap` is stack-agnostic; bringing Python just for secret scanning is disproportionate.

## R-8: Impact-analysis feed for scoped regression

**Drives**: US-C3 AC-3.

Reuse the existing `impact-analysis` skill. Call with `--since <branch-base>` to get the changed-module set + cross-module fan-out. Feed the output list to the stack's test runner as module filter (`-pl`, `dotnet test --filter`, `pytest <paths>`, etc.). Record the resolved scope in trace.

**Fallback** when `impact-analysis` is absent in the target repo: full regression (same behavior as today).

## R-9: Post-edit hook safety

**Drives**: FR-C5, US-A1 AC-8.

Hook runs arbitrary commands after file edits. Risks: infinite loop, runaway cost, accidental side-effect on tracked files outside `autorun/<PBI>` branch.

**Decision**: the hook is **opt-in** (default `false`), governed by `autorun.config.json.hooks.postEditRunTests`. When enabled, the hook:
1. Checks `git rev-parse --abbrev-ref HEAD` starts with `autorun/`; exits silently if not.
2. Only runs the scoped test command for the changed module (not full regression).
3. Emits a trace line with duration + result.
4. Respects cost-cap check; refuses to run past `cost.tokenCap * 0.9`.

## R-10: Confirmation-gate UX alignment

**Drives**: US-UX (§8), US-A1 AC-4.

VS Code: `QuickPick` (for `options`) + free-text input (fallback). CLI: JSON on stdout. The gate schema (see `contracts/gate.schema.json`) is the single contract; both harnesses render the same object.

**Key rule**: the agent orchestrating the loop **never** authors natural-language gates ad hoc — it always emits a validated gate object. Unit tests in Phase A assert schema validation for every known `gateId`.

## Decision Log

### 2026-04-24 — R-1 resolution (pre-spike)

- **Decision**: ship **Fallback A** (file-based resume token at `.github/.traces/autorun-<PBI>.resume.json`) as the **reference implementation**, regardless of whether the live Copilot CLI spike is ever run.
- **Rationale**: (a) Fallback A works in every harness including CI replay; (b) native CLI resume would be an optimization layered on top, not a different design; (c) blocking Phase A on a live CLI spike exceeds the value of the information gained.
- **Consequence**: the live spike (original R-1 §Spike plan) is demoted to an **optimization backlog item**. If a future contributor runs it and native resume works, they can add a `--native-resume` opt-in flag without breaking Fallback A.
