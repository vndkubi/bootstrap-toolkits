> Generated by: plan-implementation
> Validates the key scenarios in [spec.md](./spec.md) against the plan in [plan.md](./plan.md).

## 0. Prerequisites

- `.github/` bundle present with all 12 new files + 7 modifications from [plan.md](./plan.md) §3.
- Golden target repo cloned next to this one (Java/Maven or .NET).
- Either VS Code with GitHub Copilot + agent mode, **or** Copilot CLI installed.
- Docker for the real-local stack.
- `gitleaks` (or `detect-secrets`) on PATH if the target repo has no pre-existing scanner.

## 1. Install toolkit into the target repo

In the target repo:

```pwsh
# from the root of the target repo
copy -Recurse ..\copilot-bootstrap\.github .github
cp .github\autorun.config.example.json .github\autorun.config.json   # optional tweaks
```

If the target is CLI-driven:

```pwsh
copy .github\autorun.allowlist.example .github\autorun.allowlist
```

Edit the allowlist to permit at least: `run-tests`, `start-stack`, `lint` for your stack.

## 2. Scenario A — Happy path on a toy REST PBI (VS Code)

**Goal**: From a prepared GitHub issue to a draft PR with an evidence bundle, with ≤ 2 confirmation gates.

1. Create a GitHub issue titled `PBI-toy-1: add GET /widgets/{id} endpoint` with a short description and acceptance criteria.
2. In VS Code agent mode, run:
   ```
   /autorun #<issue-number>
   ```
3. Expect Phase 1 (INTAKE) to produce `specs/toy-1-get-widget/spec.md`. Approve at the first `business` gate (confirming AC wording).
4. Phase 2 (CONTRACT) classifies taxonomy as `api-rest` — no gate.
5. Phase 2 emits `contracts/openapi.yaml` + `quickstart.md` + `data-model.md`.
6. Phase 3 generates failing API flow tests under `tests/integration/widgets_test.*`.
7. Phase 4 emits DB seed + fixture builders.
8. Phase 5 iterates red → green; watch trace at `.github/.traces/autorun-toy-1.jsonl`.
9. Phase 6 runs functional + technical review; if clean, no gate.
10. Phase 7 writes `specs/toy-1-*/evidence-summary.md` and prints the draft PR URL.

**Pass criteria**:

- Exit outcome = `completed`.
- Working tree is on branch `autorun/toy-1`, not `main`.
- `specs/toy-1-*/contracts/openapi.yaml` exists and validates.
- `specs/toy-1-*/evidence-summary.md` exists and is committed.
- `.github/.traces/autorun-toy-1.jsonl` validates against [trace.schema.json](./contracts/trace.schema.json).
- PR body contains the Article X checklist with ✅ status.

## 3. Scenario B — CLI headless run (same PBI)

```pwsh
$env:COPILOT_HARNESS = "cli"
copilot /autorun "PBI-toy-1"
```

**Pass criteria**:

- Each `status`/`gate`/`result` line on stdout is valid JSON (`.outcome` is one of `completed|aborted|gated|failed`).
- If a gate fires, exit code ∈ `{11..17}` and `.github/.traces/autorun-toy-1.resume.json` is written.
- Resume:
  ```pwsh
  copilot /autorun "PBI-toy-1" --resume (Get-Content .github/.traces/autorun-toy-1.resume.json | ConvertFrom-Json).resumeToken --answer "api-rest"
  ```
  Expect continuation at the correct phase.

## 4. Scenario C — Abort mid-run is clean

1. Start Scenario A; interrupt at Phase 5.
2. Run `/autorun PBI-toy-1 --abort`.

**Pass criteria**:

- Branch `autorun/toy-1` still exists for inspection.
- `git status` on `main` is clean.
- `.artifacts/toy-1/abort-stash.patch` exists.
- Trace final line has `action: "abort"` with phase + reason.

## 5. Scenario D — Article X blocks an internal mock

1. Force a TDD green by editing generated tests to stub an **internal** service.
2. Continue to Phase 6.

**Pass criteria**:

- `@functional-reviewer` emits `articleXCompliant: false`.
- `@pr-manager` refuses draft; process exits with 31.
- Remedy A: revert the internal stub → rerun Phase 5+6 → pass.
- Remedy B: commit `.artifacts/toy-1/mock-exceptions.md` with two distinct signatures and `ratified: true` → rerun Phase 6 → pass with ⚠️ status in the PR body.

## 6. Scenario E — Taxonomy ambiguity gates correctly

1. Create a PBI whose body mentions **both** a REST endpoint and a Kafka event.
2. Run `/autorun`.

**Pass criteria**:

- Phase 2 emits a gate with `gateId: taxonomy-ambiguous`, `options: ["api-rest","event-driven","mixed"]`.
- Answering `mixed` produces `contracts/openapi.yaml` + `contracts/asyncapi.yaml`.
- Trace event for the gate includes the chosen option and a timestamp.

## 7. Scenario F — Negative: no TTY, CLI emits machine-readable gate only

```pwsh
# simulate no-TTY
$env:COPILOT_HARNESS = "cli"
copilot /autorun "PBI-toy-1" < $null > out.ndjson 2>&1
```

**Pass criteria**:

- No interactive prompt was attempted (no hang).
- `out.ndjson` contains a valid `kind:"gate"` line (when a gate fires) and a `kind:"result"` line at the end.
- Exit code matches the protocol.

## 8. Scenario G — Negative: shell execution disallowed

1. Remove `.github/autorun.allowlist` (or clear the `commands` list).
2. Run `/autorun PBI-toy-1` in CLI mode.

**Pass criteria**:

- Exit code 30, `gateId: authz-no-allowlist`.
- No edits applied to the working tree.
- Trace file exists with `kind: meta` + the single gate event only.

## 9. Clean-up

- `specs/toy-1-*/spec.md` front-matter updated to `status: reverted`.

## 11. Honesty caveat

Scenarios A and B require a running Copilot CLI with prompt-invocation semantics confirmed by the R-1 spike (see [research.md](./research.md)). If the spike concludes the CLI cannot invoke prompts headless, Scenario B is marked `experimental` until the fallback path (file-based resume + scripted prompt driver) is implemented. Scenarios C–G remain exercisable in VS Code mode regardless.
