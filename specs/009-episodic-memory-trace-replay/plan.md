### Data flow

```
Phase 7 (Evidence)
  ↓ capture.js
  redact-sensitive-data  ──fail──▶ abort episode write (run still succeeds)
  ↓
  score.js (tests, review, contract, rounds)
  ↓
  embed (onnxruntime-node, local)
  ↓
  write .github/.episodes/<id>.json  +  append index manifest.json
  ↓
  gc.js (if size > cap)

Phase 1 (Intake) on NEXT run
  ↓ retrieve.js
  embed(new intent)
  ↓
  cosine top-k over manifest.json, filter by threshold + score
  ↓
  format-context.js → EPISODIC_MEMORY block (positive + up-to-2 negative)
  ↓
  trace event: episode_replay{ids, scores}
```

## Risks And Rollback

| Risk | Trigger | Mitigation | Rollback |
|---|---|---|---|
| ONNX model bloats repo | LFS misconfig | LFS-track via `.gitattributes`; CI size check | Delete model; fall back to `embeddingBackend: "remote"` or feature-off |
| Prompt injection via replayed `raw_intent` | Malicious PBI text replayed verbatim | `raw_intent` never merged into system prompt; only `summary` (which is `redact-sensitive-data`-sanitized) feeds the context block | Disable replay for the repo via flag |
| Poisoned episodes | Hallucinated precedent persisted | Pre-write redaction gate + outcome_score threshold (D-4) + user `tag --bad` override (US-3 AC-4) | `gc.js --purge-below 0.5` |
| Context bloat | Too many episodes injected | Hard byte cap (default 8 KB) on EPISODIC_MEMORY block; positive-k=3, negative-k≤2 (D-5) | Lower `replayK` via flag |
| A/B self-selection bias | Users disable replay only when stuck | Force random 10% cold-start runs for control | — |
| Embedding drift across model versions | Model upgrade changes vector space | Record `embedding.model` per episode; mismatch → rebuild index | `trace-replay rebuild-index` |
| Feature ships with no evidence of benefit | No baseline runs | FR-11 + D-7 gate `review-effectiveness` report behind 20-run minimum | Feature flag stays `false` |
