# Bootstrap MCP Server — Data Model

> Generated by: plan-implementation
> Spec: ./spec.md
> Plan: ./plan.md
> Date: 2026-04-24

This document describes the internal runtime entities of the server. Wire-format schemas (JSON Schema) live under `contracts/`.

## Entities

### `ToolDescriptor`

Static description of a registered MCP tool.

| Field | Type | Notes |
|---|---|---|
| `name` | string | Snake_case, globally unique. E.g. `analyze_repo`. |
| `bucket` | enum: `read` \| `generate` \| `audit` | Drives capability wrapping. |
| `description` | string | Shown in `tools/list`. |
| `input_schema` | JSON Schema | Loaded from `contracts/mcp-tools.schema.json#<name>.input`. |
| `output_schema` | JSON Schema | Loaded from `contracts/mcp-tools.schema.json#<name>.output`. |
| `annotations.destructive` | boolean | `true` only when `bucket=generate` AND the tool supports `write: true`. |
| `annotations.idempotent` | boolean | `true` for all read/audit tools. |
| `version` | string (semver) | Tool-level semver; independent of server version. |

Invariants:

- No two descriptors share a `name`.
- If `bucket != generate`, `annotations.destructive` MUST be `false`.
- `input_schema` and `output_schema` MUST validate against JSON Schema draft 2020-12.

### `InvocationContext`

Passed to every adapter's `invoke()`.

| Field | Type | Notes |
|---|---|---|
| `repo_root` | Path | Validated absolute path; all FS access pins here. |
| `session_id` | UUID | Stable for the MCP session. |
| `allow_write` | bool | Mirrors the server's `--allow-write` flag. |
| `trace_writer` | `TraceWriter \| None` | Present only if `--trace` was supplied. |
| `redactor` | `Redactor` | Shared instance of the secret-redaction engine. |
| `audit_log` | `AuditLog` | Append-only writer for `.bootstrap-mcp/audit.log`. |
| `client_info` | dict | From MCP `initialize`: `{name, version}`. |

### `ToolResult`

Return value of every adapter.

| Field | Type | Notes |
|---|---|---|
| `status` | enum: `ok` \| `error` \| `partial` | |
| `content` | list of `ContentBlock` | MCP-compatible content blocks (text, json). Every generate/audit result includes BOTH a `text/markdown` and `application/json` block per US-4 AC-3. |
| `structured_output` | dict | Canonical JSON form — input to parity tests. |
| `provenance` | `Provenance` | See below. Mandatory on all generate tools (US-3 AC-5). |
| `hints` | dict | Optional non-critical signals (e.g. `hint.write_refused: true`). |
| `error` | `ErrorDetail \| None` | Present only when `status != ok`. |

### `Provenance`

| Field | Type | Notes |
|---|---|---|
| `tool` | string | Tool name. |
| `tool_version` | string | From `ToolDescriptor.version`. |
| `server_version` | string | From package metadata. |
| `inputs_hash` | string | `sha256(canonical_json(inputs))`, hex. |
| `timestamp` | ISO-8601 | UTC. |

### `ErrorDetail`

| Field | Type | Notes |
|---|---|---|
| `code` | string | Stable machine code. E.g. `E_PATH_ESCAPE`, `E_SCHEMA_VIOLATION`, `E_WRITE_REFUSED`. |
| `message` | string | Redacted, actionable (US-2 AC-7). |
| `hint` | string \| null | Optional remediation. |
| `mcp_code` | int | Standard MCP error code returned over the wire. |

### `ResourceEntry`

Represents one entry in the resource provider.

| Field | Type | Notes |
|---|---|---|
| `uri` | URI | `file://<repo>/...` within `repo_root`. |
| `name` | string | Display name. |
| `mime_type` | string | Always `text/markdown` in v1. |
| `size_bytes` | int | From disk at list time. |
| `last_modified` | ISO-8601 | Used to emit `notifications/resources/updated`. |

### `AuditLogEntry`

One line per write attempt, JSONL, written to `.bootstrap-mcp/audit.log`.

| Field | Type | Notes |
|---|---|---|
| `ts` | ISO-8601 | UTC. |
| `session_id` | UUID | |
| `tool` | string | |
| `inputs_hash` | string | Matches `Provenance.inputs_hash`. |
| `target_path` | string \| null | Relative to `repo_root`. |
| `outcome` | enum: `written` \| `refused` \| `error` | |
| `reason` | string \| null | For `refused`/`error`. |

## State Transitions

### Session lifecycle

```
  ┌───────────┐    initialize      ┌────────────┐
  │  STARTED  │ ─────────────────▶ │  READY     │
  └───────────┘                    └────┬───────┘
                                        │
                       tools/call       │
                                        ▼
                                  ┌────────────┐
                                  │  INVOKING  │
                                  └────┬───────┘
                                       │
                          ok / error   │
                                       ▼
                                  ┌────────────┐
                                  │  READY     │ ...
                                  └────────────┘
                                       │ shutdown
                                       ▼
                                  ┌────────────┐
                                  │  CLOSED    │
                                  └────────────┘
```

Invariants:

- No tool call is accepted before `initialize` completes.
- An `INVOKING` adapter cannot spawn subshells or perform network I/O (capability wrapper enforced).

### Write-consent decision

```
  tools/call(generate_tool, write=true)
        │
        ▼
  allow_write flag set at server start?
   ├── no  ─▶ return content; hints.write_refused = true; audit outcome=refused
   └── yes ─▶ validate target_path under repo_root
                ├── invalid ─▶ error E_PATH_ESCAPE; audit outcome=error
                └── valid   ─▶ write file; audit outcome=written
```

## Invariants (cross-cutting)

1. Every tool's output MUST validate against its `output_schema` before emission.
2. `inputs_hash` in provenance is computed over the canonicalized inputs AFTER redaction-safe normalization but BEFORE redaction — redaction never alters provenance.
3. All FS access goes through `bootstrap_mcp.fs` — no module may call `open()` directly on a user-supplied path.
4. `audit_log.append` is fsync'd per entry (small volume; correctness over throughput).
5. `trace_writer` entries conform to spec-008 `trace.schema.json`.
