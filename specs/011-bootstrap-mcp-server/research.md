## R1. Runtime language selection

### Options considered

| Option | Pros | Cons |
|---|---|---|
| **Python 3.11+** (chosen) | Official `mcp` SDK is most mature in Python; matches existing skill/spec-kit ecosystem; skills are already written as prose that maps cleanly to Python functions; `pipx` install matches target audience (devs who have Python toolchains anyway) | Cold start slower than Node/Rust; packaging cross-OS requires care for C-extension deps (keep zero) |
| TypeScript/Node | Matches `vscode-copilot-chat`; `@modelcontextprotocol/sdk` exists and is maintained | Doubles the language surface inside the repo; porting skills that already think in "read markdown, scan files" into TS is pure overhead |
| Rust | Fastest cold start; smallest binary | Porting cost too high for v1; MCP SDK less mature; community skill authors are not Rust contributors |

### Decision

**Python 3.11+**. Rationale:
- `mcp>=1.2` on PyPI is the reference server SDK.
- `pyproject.toml` + `pipx install bootstrap-mcp` is a one-line install story.
- No C extensions planned → pure-Python wheel works on Linux, macOS, Windows.
- Skill logic is naturally file I/O + regex + JSON — Python's sweet spot.

## R2. MCP protocol version floor

- **Chosen floor: 2025-06-18** (current stable at plan date).
- This version is required for:
  - structured tool output (we rely on both `markdown` and `json` representations — US-4 AC-3)
  - `elicit` capability (unused in v1 but kept as a v2 option)
  - resource subscriptions (`notifications/resources/updated`)
- SDK: `mcp>=1.2,<2` — API is stable for tool/resource/prompt registration; patch updates are safe.
- Clients verified (as of 2026-04): Claude Desktop ≥ 0.9, Cursor ≥ 0.42, Continue ≥ 0.9, Zed ≥ 0.160, VS Code ≥ 1.95 all support 2025-06-18.

## R3. Porting feasibility (pilot assessment)

The key risk is whether every chosen skill can be implemented as a deterministic pure function without needing an LLM at runtime. Pilot review of each v1 adapter:

| Adapter | LLM-free feasible? | Notes |
|---|---|---|
| `analyze_repo` | ✅ | File scans + heuristic classifiers; documented recipes per stack |
| `detect_drift` | ✅ | Manifest + scan diff |
| `audit_context` | ✅ | Deterministic — applyTo glob matching + size math |
| `audit_tools` | ✅ | Parse agent frontmatter |
| `list_skills` / `list_domains` | ✅ | Directory enumeration |
| `inspect_source_of_truth` | ✅ | Parse `SOURCE-OF-TRUTH.md` |
| `get_module_graph` | ✅ | Read `.github/module-dependency-map.json` if present; else build from build files |
| `audit_discoverability` | ✅ | Scoring formulas are deterministic |
| `validate_bootstrap_output` | ✅ | Structural + keyword checks |
| `audit_instruction_conflicts` | ✅ | Glob overlap matrix |
| `generate_spec` | ⚠️ | PRD template filling — works without LLM if the user provides structured input; degraded quality without LLM for freeform input. **Plan:** adapter accepts a structured `StorySeed` object and renders the template. Freeform-to-structured requires the host's LLM (client responsibility). |
| `generate_plan` | ⚠️ | Same pattern — structured input → template render |
| `generate_tasks` | ✅ | Deterministic parse of plan.md + contracts/ |
| `generate_pr_description` | ⚠️ | Works from git diff + template; richer output needs host LLM |

**Conclusion:** All 15 v1 tools are feasible. Generate tools that normally benefit from an LLM will degrade gracefully when the host doesn't call back through the model — they return a well-structured draft instead of a polished narrative. This matches the MCP contract (server provides tools; host provides inference).

## R4. Security & redaction

- Reuse the existing `redact-sensitive-data` skill's regex corpus (ported verbatim to Python in `bootstrap_mcp.redact`).
- Secondary scan at commit time (for audit log) via `detect-secrets` — recommended but optional in v1.
- Path traversal: `bootstrap_mcp.fs` resolves every path via `(repo_root / user_input).resolve()` and rejects anything that escapes `repo_root`.
- Supply chain: pin `mcp` SDK with `==` + hash; Dependabot grouping + weekly review.

## R5. Packaging

- Single package `bootstrap-mcp` on PyPI.
- Entry point:
  ```toml
  [project.scripts]
  bootstrap-mcp = "bootstrap_mcp.cli:main"
  ```
- Python support: 3.11, 3.12, 3.13 (Windows, macOS, Linux).
- Zero C-extension dependencies — pure wheel.
- Install story: `pipx install bootstrap-mcp` → user adds a block to their MCP client config → first tool call.
