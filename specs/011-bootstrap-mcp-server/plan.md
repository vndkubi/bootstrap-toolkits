### 3.2 Adapter layer (single source of truth claim)

Each adapter module exposes two functions:

```python
def describe() -> ToolDescriptor: ...   # name, description, input/output schema, annotations
def invoke(params: dict, ctx: InvocationContext) -> ToolResult: ...
```

Porting rules (enforced by parity tests in §5):

1. Adapter MUST produce the same JSON shape as the documented skill output.
2. Adapter MUST NOT contain prose specific to Copilot chat UX (that stays in `SKILL.md`).
3. Every adapter MUST pass inputs through `redact.redact_text` before logging and outputs through it before returning on error paths.
4. File-reading helpers are centralized in `bootstrap_mcp.fs` with an explicit `repo_root` boundary — no path escapes.

### 3.4 Transport

- **v1:** stdio only. CLI flag `--stdio` is the default and only mode.
- **v2:** HTTP transport with bearer auth, rate limit, public-bind guard, audit log (spec §US-7).

### 3.5 Consent model (v1)

- `write: true` is ignored unless the server was started with `--allow-write`.
- When `--allow-write` is absent, generate tools return content in the response and append a `hint.write_refused` field. This satisfies US-3 AC-6 ("never silently writes") without per-call elicit.
- Every accepted write is appended to `.bootstrap-mcp/audit.log` with timestamp, tool name, inputs hash, target path, and outcome.
- See §6 for the deviation from the spec's preferred `elicit`-first posture.

### 3.6 Resources

Provider enumerates the following on `resources/list` (when present in the repo):

- `file://<repo>/constitution.md`
- `file://<repo>/SOURCE-OF-TRUTH.md`
- `file://<repo>/MODULE-ARCHITECTURE.md`
- `file://<repo>/.github/domains/*.md`
- `file://<repo>/specs/*/spec.md`

Resources stream through `redact.redact_text` in-flight. Oversized files (>32 KB by default) return a truncated head plus a `cursor` parameter for paged retrieval.

### 3.7 Prompts

Canonical slash prompts are registered as MCP prompts with a JSON arguments schema. Rendering reads the existing prompt markdown from `.github/prompts/*.prompt.md` and returns a message array. See [`contracts/mcp-prompts.md`](./contracts/mcp-prompts.md).

Prompts in v1: `bootstrap-copilot`, `specify-feature`, `plan-implementation`, `generate-tasks`, `implement-feature`, `review-code-changes`.

### 3.8 Telemetry

- Off unless `--trace <path>` is supplied.
- JSONL format identical to spec-008 `trace.schema.json`; one line per tool call with `phase=mcp`.
- Each entry redacted before write.

## 6. Verification Strategy

### Test layers

1. **Unit** — each adapter, including error paths and secret-redaction.
2. **Parity** — for every adapter, feed the same inputs to the adapter and to the in-Copilot skill (or its documented output); assert byte-identical JSON. Drives NFR-7.
3. **Schema** — every registered tool's inputs/outputs validated against its JSON Schema (input on entry, output on exit).
4. **Integration** — spawn the server on stdio, drive it with a reference MCP client, assert the full `initialize` → `tools/list` → `tools/call` round trip.
5. **Security** — adversarial fixtures containing fake secrets (AWS keys, JWTs, Oracle credentials) must be redacted in logs and resource output. Uses `redact-sensitive-data` skill test corpus.
6. **Performance** — smoke timing: cold stdio init < 1.5 s (NFR-1); `analyze_repo` on this repo P95 < 2 s (NFR-2).

## 7. Risks And Rollback

### Threat model (NFR-4, spec §10)

| Threat | Mitigation |
|---|---|
| Server opened to network in stdio mode | stdio is the only transport in v1; HTTP deferred |
| Silent file writes | `--allow-write` opt-in at server start; audit log per write; AC-6 deviation documented |
| Path traversal via `target_path` | `bootstrap_mcp.fs` pins all writes to `--repo` root; reject `..` segments and absolute paths outside repo |
| Secret leaks via resources/logs | mandatory `redact.redact_text` at every emission point; adversarial test fixtures |
| Supply-chain (`mcp` SDK compromise) | pin exact version + hash in `pyproject.toml`; document upgrade policy |
| Skill-adapter drift | parity tests in CI; release-gated on drift |

### Deviation: write posture vs spec US-3 AC-6

Spec AC-6 says writes happen only after an `elicit` consent request or a per-session consent flag. Planning chose **"per-session flag (`--allow-write`) + audit log; no per-call elicit"** based on user confirmation. This still satisfies AC-6 literally (the session flag path is explicitly permitted by the AC), but is the less-interactive of the two options. Reviewers should confirm this is acceptable before M3.

### Rollback plan

- Each milestone is a self-contained merge. M1 can be reverted without disturbing M0.
- The feature ships as a separate package — uninstalling it has zero impact on the existing `.github/` bundle.
- Parity test failures block release, not merge of other milestones.
